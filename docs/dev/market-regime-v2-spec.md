# Implementation Spec: Market Regime Rule v2

Slice 1 of 1. Status: ready for pre-flight review.

Implements the "Rule v2" recommendation from
`docs/research/market-regime-classifier-v2-investigation.md` (section 4).
Read that note for evidence and context; this spec is the contract.

## Goal

Replace the v1 decision rule in `reports/market_regime_report.py` (2x-median
trend test, single-day direction, 30-day anchors) with the v2 rule: re-anchored
90-day vol band, 3-complete-day trend with hysteresis, deadbanded 3-day
direction, and a CUSUM break flag. Keep the 12-label vocabulary, the
timestamping discipline, the operating model (daily batch, offline, stdlib-only,
deterministic), and the no-lookahead guarantees.

`TREND_MULTIPLIER`, `ANNUALIZATION_SECONDS_PER_YEAR`; keep `MIN_CLOSES_PER_DAY`,
`ALL_INSTRUMENTS`, `ORIGINAL_FOLD_NAMES` and everything below intact)

```python
MIN_CLOSES_PER_DAY = 600          # unchanged
ANNUALIZATION_SECONDS_PER_YEAR = 525_600  # unchanged
TRAILING_WINDOW_DAYS = 90         # up-to-90 complete days strictly before d
BASELINE_FLOOR_DAYS = 30          # fewer prior complete days -> no_baseline
TREND_ENTRY_MULTIPLIER = 2.0      # enter trending: |r3| >= 2.0 x median(|r3|)
TREND_EXIT_MULTIPLIER = 1.0       # exit trending:  |r3| <  1.0 x median(|r3|)
EFFICIENCY_QUANTILE = 0.75        # enter trending also needs eff3 >= q75(trailing eff3)
DIRECTION_DEADBAND_SDS = 0.5      # flat iff |r3| <= 0.5 x stdev(trailing r3)
CUSUM_K = 0.05                    # CUSUM threshold (relative sigma deviation units)
CUSUM_H = 4.0                     # CUSUM action limit
```

The candidate sets (anchor {90, 60}; entry {1.5, 2.0, 3.0}; exit {1.0, 1.5};
efficiency quantile {0.50, 0.75, 0.90}; deadband {0.25, 0.5}; CUSUM
k {0.05, 0.10}, h {4.0, 6.0}) are documented in the constants-block comment, in
the map `rules` block (R7), and in the preregistration (R10). The primary
variant above carries the decision; selection on a training window is deferred
to the evaluation phase (investigation note section 6) and is NOT part of this

### R2. `DayObservation` — add one field

the day's one-minute closes (0.0 for a flat or single-point day).
`load_day_observations` already computes this as `denominator`; store it.
All other fields, and the query/aggregation behavior, are unchanged.

### R4. `classify_days` — replace internals, keep name and signature

Process observations in chronological order. Maintain:

- `complete_prior: list[DayObservation]` — complete days, appended AFTER each
  complete day is classified.
- `complete_stats: list[tuple[float | None, float | None, float | None]]` —
  per prior complete day, `(r3, eff3, sigma)` computed when that day was
  processed; aligned with `complete_prior`.
- Trend state: `trending: bool`, initial `False`.
- CUSUM state: `(s_plus, s_minus) = (0.0, 0.0)`.

For each day `obs`:

1. `close_count < MIN_CLOSES_PER_DAY` -> status `insufficient_data`, all
   sub-labels/anchors/flag None, trend and CUSUM state unchanged, day NOT
   added to `complete_prior`. (Existing behavior, preserved.)
2. Complete day, `len(complete_prior) < BASELINE_FLOOR_DAYS` -> status
   `no_baseline`, all sub-labels/anchors/flag None, trend and CUSUM state
   unchanged, day IS added to `complete_prior`/`complete_stats` (with r3/eff3
   computed where possible — see 4).
3. Complete day with floor met. Let `window = complete_prior[-TRAILING_WINDOW_DAYS:]`
   (up to 90 complete days STRICTLY before d). Compute anchors from the window;
   for every anchor, if the filtered (None-excluded) sequence is empty, the
   anchor is `None` (never raise `StatisticsError`):
   - `sigma_median_90 = median(window sigmas)` (None sigmas excluded)
   - `sigma_median_30 = median(most recent 30 window sigmas)`
   - `abs_r3_median = median(|r3| over window r3s)` (None r3s excluded)
   - `eff3_q75 = quantiles(eff3s, n=4)[2]` — i.e. `statistics.quantiles`
     exclusive method; None if fewer than 2 non-None eff3 values
   - `r3_sd = statistics.stdev(window r3s)` (None r3s excluded); None if fewer
     than 2 non-None values
   Compute day features (span = the 3rd-most-recent complete day at or before
   d — i.e. `base = complete_series[-3]` where `complete_series` includes d as
   its last element — through d; that span contains exactly 3 complete days):
   - `r3 = obs.last_close / base.last_close - 1.0`, None if either close is
     missing or `base.last_close <= 0`, or if there are fewer than 2 prior
     complete days.
   - `eff3 = |obs.last_close - base.last_close| / sum(intraday_path_length over
     the 3 complete days in the span)`, None if the denominator is 0.
   - `sigma_dev = (sigma_d - sigma_median_90) / sigma_median_90`, None if
     `sigma_median_90` is None or <= 0.
   Decision axes (any comparison against a `None` anchor or feature is simply
   not evaluated — never raise `TypeError`):
   - **Vol**: `high_vol` iff `sigma_d >= sigma_median_90`, else `low_vol`.
     (`sigma_d` is None only if the day had < 2 log returns; with 600 closes
     this cannot occur — treat as `low_vol` if it does.)
   - **Trend** (hysteresis state machine; state persists across days):
     - if not trending and `r3`, `eff3`, `abs_r3_median`, `eff3_q75` are all
       not None: enter trending iff `|r3| >= TREND_ENTRY_MULTIPLIER *
       abs_r3_median` AND `eff3 >= eff3_q75`.
     - if trending and `r3` and `abs_r3_median` are not None: exit to
       non_trending iff `|r3| < TREND_EXIT_MULTIPLIER * abs_r3_median`.
     - otherwise (any required value None): state unchanged (cannot occur
       when the floor is met, but must be safe).
   - **Direction**: if `r3` is None: `direction = None`. Else `flat` iff
     `|r3| <= DIRECTION_DEADBAND_SDS * r3_sd` (treat `r3 == 0` as flat); else
     `up`/`down` by sign of `r3`. If `r3_sd` is None: `flat` iff `r3 == 0`,
     else by sign. (A classified day always has a non-None direction.)
   - **Break flag** (two-sided CUSUM on `sigma_dev`, state persists, initial
     (0,0)):
       `s_plus = max(0.0, s_plus + sigma_dev - CUSUM_K)`
       `s_minus = min(0.0, s_minus - sigma_dev - CUSUM_K)`
       `break_flag = (max(s_plus, -s_minus) > CUSUM_H)`; if flagged, reset
       `(s_plus, s_minus) = (0.0, 0.0)`. If `sigma_dev` is None: flag False,
       state unchanged.
   - status `classified`; `regime_label = f"{vol}_{trend}_{direction}"`.
   Append `obs` to `complete_prior` and `(r3, eff3, sigma_d)` to
   `complete_stats`.

Invariants (test-enforced): every statistic for day d uses only complete days
strictly before d; trend and CUSUM state carry forward in time only; a future
day never changes any earlier label.

### R9. Tests (`tests/test_market_regime_report.py`)

Keep the in-memory `DayObservation` fixture style (no parquet). The `_obs`
constructor must gain `intraday_path_length` (and a way to set distinct
`last_close` values, since v2 derives `r3` from closes, not from a fixture
field). All expected values must be hand-verifiable from the R4 formulas —
never derived by running the implementation.

Required tests:

- **T1 hand-computable labels (rewrites the v1 test).** A >= 34-day fixture
  where the first 30 complete days have a uniform, known path and probe days
  exercise: vol axis at the anchor boundary; trend entry (both conditions met);
  direction up/down/flat via the deadband. Assert the exact `regime_label`
  strings for probe days.
- **T2 floor.** A day with exactly 29 prior complete days -> `no_baseline`;
  the next day with exactly 30 -> `classified`.
- **T3 defect fix (the documented v1 bug).** Trailing window where the
  efficiency median exceeds 0.5 (e.g. all prior eff3 = 0.6): a probe day with
  `|r3| >= 2x median(|r3|)` and `eff3` at/above q75 MUST be labeled trending.
  (Under the v1 rule this threshold was unreachable — the regression guard.)
- **T4 hysteresis.** After an entry day, a day with `|r3|` between
  `EXIT_MULT * median` and `ENTRY_MULT * median` stays trending; a day below
  `EXIT_MULT * median` exits; re-entry afterwards requires the full entry
  condition again.
- **T5 CUSUM.** Prior days with `sigma_dev == 0` (uniform sigma) -> no flags;
  a shock day (`sigma_dev = 9.0`, e.g. sigma 10x the 90-day median) ->
  `break_flag` True on that day only; the following normal day -> False
  (reset works).
- **T6 no lookahead.** Keep the existing pattern: classify a series, replace
  the last day with an extreme one (huge sigma / r3 / eff3), assert all
  earlier `DayRegime` rows are unchanged.
- **T7 insufficient-day exclusion.** An `insufficient_data` day with extreme
  values must not enter any baseline: assert the recorded `anchors` of a later
  day equal hand-computed values over complete days only, using a statistic
  that a leak would change (use `r3_sd` — the sample standard deviation is not
  robust to one extreme point; robust statistics like medians are acceptable
  supplementary assertions).
- **T8 schema invariance (BNB schema-1 guard).** Two observation series that
  are identical except `manifest_schema` (1 vs 2) must classify to identical
  output except that field — pins that classification never reads the schema.
- **T9 attribution + duplicate-day rejection.** Keep the existing
  `SourceSplitAttributionTest` semantics, adapted to the new fields.

## Documented deviations from the investigation note

- **D1 — CUSUM statistic.** The note prescribes a MAD-based robust z. On a
  zero-dispersion trailing window (all sigmas equal) MAD = 0 and the z is
  undefined; the natural fallback (z = 0) makes the flag permanently blind
  exactly in that case, and no fallback scale is principled. v2 therefore runs
  the CUSUM on the relative sigma deviation
  `d_d = (sigma_d - median_90d) / median_90d` (k = 0.05, h = 4.0) — scale-free,
  no degenerate case (guard: median <= 0 -> no flag), and hand-testable. The
  preregistration records this substitution explicitly.
- **D2 — function name.** The note names the rule function
  `classify_days_v2`; v2 keeps the existing `classify_days` name (single
  module API, no version suffix) and marks the rule version via the map
  `schema_version` (1 -> 2) and the `rules` block.
- **D3 — baseline floor.** v1 classified a day with as few as 1 prior complete
  day. v2 introduces the explicit 30-day floor (note section 4.3), so on the
  current 51-day sample each instrument classifies 21 of 51 days (was 48).
  This is an honest consequence of the 90-day anchor design, not a regression.
